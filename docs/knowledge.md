# 画像スタイル研究ノート（imagin）

元のナレッジベースから、計測ツール・理論・外部情報・コンポジット結果を抜粋。

### 計測ツールキット（このリポジトリの `analysis/`。依存は requirements.txt）
| スクリプト | 測るもの |
|---|---|
| `depth_compare.py` | Depth Anything V2で深度を推定し、手前・中景・遠景・空の帯ごとに明るさ（L*）、影の暗さ（p5）、コントラスト、色味（b*）、描き込み量を測る |
| `edges.py` | 深度が急に変わる所（遮蔽の輪郭）で、深度の差、明暗の分離、縁の光（リム）、にじみ（halo）、輪郭の目立ち度を測る |
| `metrics2.py` | 明度の分布、ノタン（明暗の塊の分かれ方と断片化）、ハイライトの散らばり、彩度、色温度、色相の多さ、周波数帯ごとの描き込み量、静かな面の割合 |
| `metrics3.py` | 線（量、暗さ、線の色、太さ、長さ、直線性）、タッチ（粒子、筆致の方向、色数、ボケ）、シェーダー（明暗の境目の硬さ、階調の段数、小さなハイライト） |
| `metrics4.py` | ライティングと仕上げ（ダイナミックレンジ、黒と白の点、ブルーム、ビネット、空の上部の暗さ、分割トーン、霞、色収差、光源の数） |
| `metrics5.py` | 形状（法線のばらつき、Lambertでの当てはまり、推定した光源の仰角と方位、陰影の段差度、bump） |
| `pbr.py` | PBRマップの観点で推定（アルベドとシェーディングの割合、ラフネス、スペキュラ、キャビティ、エミッシブ、SSS、フロー、ディスプレイスメント、アルファ） |
| `comp.py` | 構図（斜めの透視線の本数、消失点への収束度と位置）、明暗の境目の色の帯 |
| `stylemetrics.py` + `measure.py` | 上記をまとめたもの。`measure.py IMAGE [--panels]` で、目標の昼画像の範囲に何項目入るかを出す |
| `composite.py` | 深度を使った2Dコンポジット（手前を暗く、S字カーブ、ビネット、縁の光を抑える）をグリッドサーチで最適化する |

- 1枚の絵からの推定なので限界がある。光源の仰角（10°に張り付くことがある）、ランプ、AOは信頼できない。メタリック、クリアコート、シーン、異方性は2D画像からは推定できない。

## 3. ChatGPT（画像生成）の癖と、効いたプロンプト技法

1. **行き過ぎる**: 直すよう指示すると必ず逆側まで振れる（v4→v5→v6→v7）。「半分だけ戻す」「前の版と前々版の中間」と指示すると収まる。
2. **暗さを嫌う**: 暗部の面積と明暗差は、どう指示しても足りない。目標値より強めに指定する（暗部の面積0.45など）。
3. **保持リストは構図の細かさを固定する**: 保持リストに電柱などの要素を並べると、要素が減らない。構図を減らすときは、保持リストも絞る。
4. **グリッド（2×2）は1枚あたりの解像度が約500px**になる。細部を重視するときは1枚ずつ生成する。
5. **前の出力を添付して描き直させると、色がよく保たれる**（編集として扱われる）。
6. **渡し方の比較**（同じ場面・同じ目標スペックで、23指標中いくつが目標の範囲に入ったか）
   - 0〜1のパラメータ（0と1の意味を言葉で明記したJSON）: **19/23（最良）**
   - 文章: 12〜17/23
   - 方程式: 15/23（方向は伝わるが強さが行き過ぎる。ビネットの式は逆に効いた）
   - ヒートマップ（C）: 未実施（送ってよいか確認中）
7. **Image-to-JSON**（参考画像の画風をJSONに書き出させ、それを設計図にする）＋OpenAI公式の「Preserve / Change / Borrow」テンプレートが効いた。
8. **素人の落書き風**: 誰が・何で・どんな状況で描いたかを具体的にする（「会議中に会社員が安いマーカーで2分」など）。「参考画像より上手く描かない」「下手でいいと明示的に許可する」も効く。線の本数も数値で指定する（顔1つにつき30〜40本など）。
9. アーティスト名を出すと断られやすいので、画風は具体的な技法で書く。
10. 数値の目標を先に計測し、プロンプトに具体的なHEXや比率で書くと色の問題は一発で直った（v4で色系の指標がすべて範囲内に入った）。

## 4. 理論の要点（詳細は style-theory.md）

- **暖かい光と冷たい影**: 直射日光は大気で青が抜けて暖色になり、影は散乱した空の光で照らされる（レイリー散乱）。補色同士は並べると互いを強める（シュヴルールの同時対比）。目標では明部が106°、暗部が261°。
- **人は奥行きや形を主に明るさで読む**（Livingstone）。明暗差と暗部の面積が、フラットでなく見えるための第一条件。
- **線に色を付ける（色トレス）**: 線が塗りに溶け込み、風景として読まれる。細い線の多さが情報密度になる。
- **テクスチャ勾配**（Gibson）: 描き込みの細かさが距離とともに変わること自体が、奥行きの手がかりになる。
- **小さなハイライトとヒストグラムの歪度から、艶が知覚される**（Motoyoshi 2007）。
- **リム（縁の光）は3DCGの癖**。現実の逆光で縁が光るのは、半透明の物だけ。
- **ビネット**はレンズの周辺減光（cos⁴則）の模倣。空の上部だけを暗くするパラとは別の処理。
- **ブルーム**はグレア錯視で、「画面の白より明るい」ことを伝える。
- **トゥーンシェーダー** I = step(N·L − t): 明暗の境目で明るさが跳ぶ。目標の段差度はこちらの版より1桁大きい。
- **影の長さ** = 高さ / tan(仰角)。仰角35°なら高さの1.43倍、55°なら0.70倍。
- **輪郭をまたいで深度が大きく跳ぶ**（少ない層を大きく離して重ねる）のが、アニメ背景らしい奥行き。

## 5. 外部から受け取った情報（ユーザーが共有したもの）

### 5.1 シェーダーのテクスチャマップ一覧（PBR）
- **基本色**: アルベド／ベースカラー（陰影なしの純粋な色）、ディフューズ（固定の陰影込み）
- **凹凸**
  - ノーマル（青紫色の画像。反射で凹凸を表現し、輪郭は変わらない）
  - バンプ（白黒の旧式）
  - ハイト／キャビティ（溝の深さ。汚れを溜めるマスクにも使う）
  - ディスプレイスメント（実際に形を変形させ、輪郭も変わる）
  - ベクターディスプレイスメント（XYZの3方向に変形。オーバーハングする形も作れる）
- **質感**
  - ラフネス（白いほどザラザラ）／グロッシネス（ラフネスの反転）
  - メタリック（白が金属、黒が非金属）
  - スペキュラ（ハイライトの強さと色）
  - クリアコート（透明なコーティング層）
  - シーン（布の産毛のような反射）
  - 異方性（ヘアラインや髪の、方向のあるハイライト）
- **光と影**: AO（隙間に光が届かない影を焼き付ける。立体感が大きく上がる）、エミッシブ（自己発光）、オパシティ／アルファ（透明度。葉やフェンスの網目）
- **透過**: SSS（肌・ロウ・翡翠など、内部で光が散乱する）、トランスルーセンシー（薄い葉や耳が裏から透ける）
- **アニメ調**: MatCap（ライティングを焼き込んだ球の画像）、ランプ（グラデーション）マップ（トゥーンシェーダーの影の境界のボケ具合と影色を制御する）
- **その他**: IDマップ（パーツごとの色分け）、フローマップ（流れの方向をベクトルで指定）、ディテールマップ（近くで見たときだけ効く微細なノイズ）

### 5.2 ディスプレイスメントマップ（2つの意味）
- **3D**: 白黒の高さマップで、実際に表面を変形させる（輪郭も変わる）
- **2D動画編集**（After Effects、AviUtl）: 参照画像の濃淡に応じて画素を水平・垂直にずらす。揺らぎ、グリッチ、映り込み、写真に奥行きを出す演出に使う

### 5.3 2Dコンポジット（2D合成）
- 別々に作った素材を重ね、なじませて、1枚（または1本）に仕上げる最終工程
- やること: 空気遠近（奥を青く霞ませる）、光と影の演出（フレア、光漏れ、足元の影）、カラーグレーディング（色味の統一）、レンズ効果（被写界深度、ビネット）
- ソフト: 動画はAfter EffectsやNuke、静止画はPhotoshopやCLIP STUDIO
- 例: 奥の山だけを切り抜いて青白くぼかす、手前に黒のグラデーションを重ねて影にする
- **本プロジェクトでは `composite.py` として、深度駆動の処理をPythonで自動化した**

### 5.4 奥行きと情緒を出す構図のアドバイス（外部AIの回答）と、実測での検証
- パースの線を1つの消失点に集める（まっすぐ奥へ伸びる道、電柱や家並みを規則的に並べる）→ **支持**（目標は斜めの透視線が約3倍、消失点は中央付近）
- 手前を暗く、奥を明るく → **支持**
- ハイトやディスプレイスメントで経年の粗さを出す → A・Bはすでに目標より粗く、**不要**
- ランプで影の境目に青みや赤みを混ぜる → 目標の画像群では**確認できず**
- 奥を青く白く霞ませる（Zデプスのフォグ）→ 目標の画像群とは**逆**（霞は低く、奥は黄色寄り）
- 結論: 外部AIの一般論は、実測で検証してから採用する。

### 5.5 深度マップとディスプレイスメントで静止画を立体的に動かす（note.com/tomoex/n/n65ddeee2778f）
1. Photoshopのニューラルフィルター「深度ぼかし」で深度マップだけを出力する（手前が黒、奥が白）
2. After Effectsで深度マップにガウスブラー（100）をかけて非表示にする（輪郭が裂けるのを防ぐ）
3. 写真に「ディスプレイスメントマップ」をかけ、マップに深度レイヤー、「エフェクトとマスク」、色成分は輝度を指定する
4. 最大の水平・垂直の置き換え量にキーフレームを打つと、視差のあるカメラの動きになる
- AviUtlでも同じことができる。深度マップはレンズのピントぼけにも使える
- 本プロジェクトでは、Depth Anythingの深度で同じ処理をPythonで再現できる（未実装）

## 6. ローカルでの2Dコンポジット（composite.py / composite2.py）の結果
- composite2（操作を増やし、座標降下で最適化、フル解像度で出力）: Aは21/22（`encA-composite2.png`）、**A2は22/22（全指標が範囲内。`encA2-composite2.png`、S字カーブ0.25、ビネット0.2、縁の光の抑制0.2、彩度0.85）**
- 生成でA2のパラメータを使い、仕上げにcomposite2をかける流れが、現時点で最良
- 符号化Aの画像に、深度を使った処理を54通り試した。最良は、手前の暗さ0.45、S字カーブ0.5、ビネット0.35、縁の光の抑制あり
- 目標の範囲に入った指標: **19/22 → 20/22**。明るさのばらつき（19.3→23.8）と暗部の面積（13→27%）が範囲内に入った
- 残った問題: 縁の光（4.1→1.4、まだプラス）と、線の量が行き過ぎ（コントラストを上げたことで増えた）
- 最良の値がグリッドの端だったので、範囲を広げればさらに改善する余地がある。出力は760px高なので、本番ではフル解像度で処理する
- 出力: `output/encodings/encA-composite.png`
- 結論: **生成で色と描き込みを合わせ、暗部・コントラスト・ビネットはローカルのコンポジットで確実に合わせる**という分担が有効（モデルは暗さを嫌うため）

- **場面によってパラメータを変える**（田んぼの場面、2026-09-20）: 踏切向けに強めた暗さ（暗部0.5、ビネット0.8）は、明るい田園の場面では暗すぎた（暗部42%）。0.30／0.40に下げると、今度は暗部19%で明るすぎた。**最初は目標値どおりの値で生成し、足りない分は仕上げ処理で補う**方が安定する
- composite2に「露出」「空の上部を明るくする」「逆方向のビネット」を追加した（明るくする方向の操作が無いと、暗すぎる生成を直せない）。田んぼの1枚目（暗い版）: そのまま12/22 → 仕上げ後18/22 → ESRGAN後17/22（平均値からの距離0.335）
- ビネットと空の上部の暗さの指標は、構図（左上を大木が覆う等）に引っ張られる。風景の構図が違う場面では参考程度にする
- **C（ヒートマップ画像を4枚添付）は2回とも送信自体が失敗**（「generation never started」）。画像を多く添付するとopengptの送信が不安定になる
- A3（暗さと縁の光をA2よりさらに強めた指示）は、A2より悪化した（19→17/22）

### 現時点の最良パイプライン（2026-09-20）
1. 生成: `base.txt` + 0〜1パラメータ（`A2_params.txt`、または群ごとの `recipe_*.json`）を、元写真を添付してChatGPTに送る
2. 仕上げ: `composite2.py`（深度を使ったS字カーブ、ビネット、縁の光の抑制、彩度）。目標の指標に合わせて座標降下で自動最適化する
3. 高解像度化: `upscale.py`（Real-ESRGAN x4plus anime 6B、spandrel、MPS）で1080×1920と2160×3840を出す
